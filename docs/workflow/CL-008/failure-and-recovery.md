## 执行升级要求

合成场景对应真实测试必须记录：受控夹具版本/SHA、Job/trace/admission ID、明确注入点、
API/DB/Temporal/上游各自观察、页集合/结果可读性、调用/费用回执、物理停止/清理回执、
可操作恢复及责任人。实际日志只能用最小引用/错误码，禁止打印原文/凭据/签名 URL。

真实并发验证需要两事务/屏障分别排列“准入/接纳先”与“取消/删除先”，验证唯一键、固定锁序、
死锁有界重试及当前权限再查；不能把顺序内存演练叫并发压测。
Temporal 必须运行相应业务/桩 workflow 并验证重启与历史重放，未知上游用可控进程或 MockTransport 注入，
不得为验证重试向真实模型平台无限重发。

人工入口至少能显示失败范围、retryable=false 原因、unknown 在途及独立停止/费用状态；
A 决定对账/重放，B 执行恢复，C 复核删除不可读和副本证据，D 后续核验用户文案。
这些是职责提案，未冒充真实成员已指派/签审。处理期限/限额随批准配置记录，不擅自冻结 SLA。

当前业务 schema 尚无 Outbox、Inbox、admission 或治理台账；全部 SQL/权限/恢复性质待实现验证。
真实恢复任何台账缺失、上游费用/停止未知，维持阻断/待对账而不是把 FAILED 当作已恢复或费用归零。
