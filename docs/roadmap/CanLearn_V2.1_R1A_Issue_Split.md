## 2. 录入及关闭规则

- 本表是**拆分草案**，不是执行队列。创建 Issue 前先确认实际负责人、非作者审核人与验收人；三人未填齐的卡保持 `status:blocked`，不以“文档写完了”替代指派。
- 父卡只做范围与综合验收，不作为下游子卡的开工门槛（沿用 [R0 拆分](CanLearn_V2.1_R0_Issue_Split.md#录入及关闭规则) 的口径）。子卡的“依赖”指开工所需的具体输入；未列出的全局 DoD（权限、幂等、版本、删除、日志脱敏）仍然适用。

- 关闭前必须附：变更范围、`pnpm verify` 结果（涉及代码/契约/配置时）、对应 E 层用例的实际执行状态、测试数据合法性说明、已知限制与回退方式。文档/研究类产出不强行附 PR 或编造测试结果。

## 3. 拆分原则

**为什么用 0.5–2 天粒度。** R1A 的 19 张卡都横跨“契约—数据—权限—异步—存储”多个面，单卡真实工作量远超一个评审周期；而当前阶段的外部条件（合法样本、签审、真实用户、供应商）随时可能把一张大卡整体钉死。按 0.5–2 天切片后，未受阻的部分可以连续产出可复核证据，受阻部分只在确切的验收点显示为 Blocked，不会让整张卡停在“进行中”而无法判断缺什么。这也与 [R09](../security/CL-014/risk-and-signoff-register.md#2-风险台账) 对四人容量的判断一致。

**父卡与子卡的职责边界。**

- 父卡（CL-101～CL-119 本身）只写：范围、非范围、绑定哪些契约章节、综合验收用例、No-Go 边界、以及“哪些准入条件仍未满足”。父卡不写实现步骤。
- 子卡（创建时再拆）只写：一个可独立检验的断言、所需输入、可回退的最小改动。子卡完成不自动关闭父卡。
- 数据与契约类改动以“可对账的引用”为产出，不以“新增了一个文件”为产出；验收断言必须能在没有作者解释的情况下被第三方重复。

**每张卡的必备字段。** 下文每卡固定五段：目标/产出、依赖、验收/证据、No-Go 下的可推进边界、契约准入映射。缺任一段的卡不进入创建队列。

## 5. 按工作流分组的卡片详情

分组与第 4 节总表一致，其中一处相对“默认按前端/后端切”的做法做了调整：**(a)** CL-113 放进“质量、检索与纠错”而不是“前端体验”——它的产出是 `PATCH .../pages/{pageIndex}` 的修订与失效传播（`area:api`），与 CL-108/109 的质量门和索引失效闭环同域；若放到前端组，会切断它对 CL-109 的硬依赖，也让纠错语义失去唯一归属卡。**(b)** CL-110 与 CL-113 同组，因为两者共同定义“引用能否回到同版原件”，是 CL-112 的共同上游。**(c)** CL-119 是跨卡 E2E 证据汇总，与 CL-111/112 一起作为对外可观察面，不单列，否则会出现一张没有交互面的“验收卡”。

### 5.1 身份与授权基础

#### CL-101 `[R1A][P0][api]` 实现真实身份与资源权限校验

- **目标/产出：** 基于 [ADR-0003](../architecture/ADR-0003-identity-and-private-storage.md) 选定的身份方案，落地会话/鉴权与空间成员权限，提供统一 Guard/Policy，使所有业务路由在控制器之前完成“当前会话 → 账户 → 空间 → 资源归属 → 用途”解析；产出为鉴权模块、策略表、以及一组可重跑的真实 HTTP/数据库回归（取代 [CL-005a 记录中不可重建的旧探针](../architecture/CL-005/identity-storage-acceptance.md#证据与认证回归)）。
- **依赖：** CL-004、CL-005、CL-006。
- **验收/证据：** 匿名请求 401、未验证邮箱 403 `EMAIL_UNVERIFIED`；越权 ID 与不存在的资源返回**同一个** 404，不泄露拥有者、版本或删除状态；不同账户之间看不到彼此内容，也不能通过缓存命中判断对方是否持有文件；过期凭证、空间切换、撤销后的会话均被拒。注册链路遵守 [CL-005a 事务与通知约束](../architecture/CL-005/identity-storage-acceptance.md#注册与邮件交付)：邀请码条件消费、未验证账户、验证记录与 NotificationOutbox 同事务，事务内不调用 SES。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：策略与 Guard 实现、合成账户生成器、真实 PostgreSQL 事务/回滚断言、CSRF/Origin/限流/枚举与日志脱敏负例。**必须等外部条件**：真实 SES 发信与真实邮箱域名验证要等供应商准入与外部隐私签审；`#49` 真实用户 UAT 与 `#20` 访谈决定会话时长是否被用户接受，但**不改变** [CL-005a 候选值](../architecture/CL-005/identity-storage-acceptance.md#未决项必须在节点前定案) 的待批状态。
- **契约准入映射：** 本卡不新增业务端点，因此**不单独触发** planned→implemented。它为其他所有端点的**条件 2**（会话、验证邮箱、Origin/CSRF、服务端空间归属、越域 404、角色负例）提供证据基础；未通过时任何端点都不得升级为 implemented。

#### CL-102 `[R1A][P0][web]` 创建学科空间与私有学习空间

- **目标/产出：** 私有空间的创建/列出/修改与学科归属，支持 408、四六级与“尚无公共包的第三学科”；产出为空间 CRUD 端点与其 DTO，以及 Web 侧的空间选择与切换。
- **依赖：** CL-006、CL-101。
- **验收/证据：** 三类学科都能建立独立空间，名称与目录不写死 408；读写隔离、删除状态、重复创建请求（同键同载荷返回同一资源）均经 API 测试；空间归属只由服务端会话决定，客户端传入的 `space_id` 只作过滤。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：合成账户下的空间 CRUD、隔离与重复请求断言。**必须等外部条件**：第三学科的实际学科包内容要等公共内容签审（`#14` / R1B 的 CL-201/202），本卡只保证“无公共包的学科仍能建私有空间”这一结构事实。
- **契约准入映射：** 空间 CRUD **当前不在** [`canlearn.v1.yaml`](../../contracts/openapi/canlearn.v1.yaml) 的关键端点内（[CL-012c D12](../quality/CL-012/uat-matrix-and-observation-log.md) 记录了该缺口）。因此本卡**第一步是补契约**，再谈准入；届时需覆盖条件 1、2、5、6。在契约补齐前，本卡只能交付内部实现与合成测试，不得被下游卡当作已可用的依赖。

### 5.2 文档与版本

#### CL-103 `[R1A][P0][api]` 设计并落实不可变原件、权限域和权利记录

- **目标/产出：** 对象存储 key 规则、服务端加密、签名 URL 策略、文件哈希、资料版本与派生资产引用、生命周期元数据；产出为 `documents`/`document_versions` 的迁移与所有权实现，按 [CL-006c 写入矩阵](../architecture/CL-006/ownership-and-migrations.md#写入矩阵) “文档/解析/标准块/索引代”一行归 Document API 权威写入。
- **依赖：** CL-004、CL-005、CL-101。
- **验收/证据：** 上传新版本不覆盖旧原件；引用可解析到原始版本（记录真实 `VersionId`，禁止默读 latest）；对象读取、临时 URL、哈希去重与删除受同一权限域约束；两个合成账户上传同一份文件时**不合并**私有资产。加密与版本策略按 [CL-005a 存储行](../architecture/CL-005/identity-storage-acceptance.md#未决项必须在节点前定案) 在**首个对象写入前**定案并留配置证据。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：桶策略/前缀隔离/加密配置的合成验证、版本枚举与精确读取、哈希去重不跨域、迁移与回滚演练（[CL-005a 真实 COS 合成验收矩阵](../architecture/CL-005/identity-storage-acceptance.md#真实-cos-合成验收矩阵) 的六类场景）。**必须等外部条件**：真实 COS 桶与最小权限身份（供应商准入）、[CL-014 外部签审登记](../security/CL-014/risk-and-signoff-register.md#3-外部签审登记) 中的权利与隐私两行；`#39–#41` 合法样本决定“真实原件”进入测试环境的时机。未获批准的加密方案与版本策略不得对真实用户作任何承诺。
- **契约准入映射：** 覆盖 `/v1/documents`、`/v1/documents/{documentId}/versions`、`/v1/documents/{documentId}/versions/{versionId}` 的**条件 1、2、3**（版本 ETag）、**5、6**。条件 4（202/Job 部分可用与清理）由 CL-105/107 承担。升级前提：专用测试桶、两个合成账户、版本/删除负例齐备，且 [CL-005a 存储决策](../architecture/CL-005/identity-storage-acceptance.md#未决项必须在节点前定案) 已批准。

#### CL-104 `[R1A][P0][api]` 提供 PDF 上传会话和准入检查

- **依赖：** CL-103、CL-109、CL-114。
- **验收/证据：** 并发解析/重试/晚到结果不能复活已删数据；在线删除可追踪，检索与签名 URL 失效；重复删除幂等；备份不承诺即时物理删除，而按明确期限清除/防恢复；未知供应商副本不填 `confirmed`；删除演练出证据（对应 E-B09）。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：墓碑、访问阻断、依赖闭包遍历、晚到拒收、重复删除幂等，在合成桶与合成账户上验证。**必须等外部条件**：**备份保留期与删除后历史事实保留未决**（[OQ-02](#7-需要人工决定的开放问题)）、Q03/Q04/Q07/Q09；真实恢复演练要等独立备份环境；外部副本清理要等供应商准入。
- **契约准入映射：** 覆盖**全部六条**，其中条件 6 的“原件/供应商/范围获准”是硬前提。**未解除 Q03/Q04/Q07 前，任何“删除完成”的对外文案都不成立**；只能写“在线访问已阻断，残余副本按获批规则跟踪”。

#### CL-118 `[R1A][P0][security]` 自动化文件与检索的越权/注入专项测试

- **目标/产出：** 恶意 PDF/HTML/公式、文件内指令、跨空间引用、缓存时序、签名 URL 泄漏、删除竞态的合法夹具与自动化测试。
- **依赖：** CL-104、CL-109、CL-117。
- **验收/证据：** 数据内指令不能提升系统指令权限或调用未授权工具；恶意内容不能执行服务器命令/脚本；泄露路径修复后加回归；阻断级越权为零；测试数据不含真实私有资料。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：全部夹具与测试（合成/原创），以及 CI 中的阻断级门槛。**必须等外部条件**：真实攻击面（生产网络、真实供应商响应、真实 CDN/缓存）要等目标环境与供应商准入；`#44` 的解析产物格式若变化，注入夹具需重跑。
- **契约准入映射：** 不新增端点；为条件 2、3、4、6 提供负例证据。这些负例是其他端点升级 implemented 的**前置条件**，不能反向用端点已实现来证明测试充分。

### 5.7 前端体验与端到端验收

#### CL-111 `[R1A][P0][web]` 上传页展示费用预估、任务进度与失败范围

- **目标/产出：** 文件/页范围确认、使用权声明、排队/解析/质检/部分可用/失败/取消状态，安全的轮询与重试入口；对应 UAT 的 P-B02/P-B03/P-B05/P-B06。
- **依赖：** CL-104、CL-105、CL-108。
- **验收/证据：** 用户能看到成功页与失败页，不把一页成功称为全部完成；取消与重试不重复生成新文档；移动端与键盘可用；错误文案与状态机一致，不用动画代替文字。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：基于 mock 状态与合成 API 的页面、状态文案、键盘与移动检查（沿用 `/prototype` 的既有实现与测试口径）。**必须等外部条件**：**上传限额未冻结**（[OQ-01](#7-需要人工决定的开放问题)）导致非法输入提示无法定稿；超时/503 的文案映射（D07）未定；真实用户观察要等 `#49`/`#20`。
- **契约准入映射：** 无端点，依赖 CL-104/105/108 的契约确认。**契约未定前不得自造状态或入口**（[UAT 层级规则](../quality/CL-012/uat-matrix-and-observation-log.md) 的“阻塞—契约”）。

#### CL-112 `[R1A][P0][web]` 实现 PDF—结构化内容双栏阅读和引用回跳

- **目标/产出：** 原件左侧/章节与内容右侧；点击引用定位页与区域；展示缺页、解析版本、来源权限与低可信标记；对应 P-B01 与 E-B01。
- **依赖：** CL-110、CL-108。
- **验收/证据：** 双栏页序与区域经人工抽检；移动端可切换视图；不可访问/失效引用不泄露缓存内容并给出明确提示；回跳确实落到同版 PDF 的同一区域，而不是只切页码。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：双栏布局、引用高亮、失效态与移动切换，用合成 PDF 与固定区域数据。**必须等外部条件**：**原件读取端点与完整回跳契约为 D13 未决**；真实 PDF 渲染/大文件性能要等容量实测；用户体验结论要等 `#49`。
- **契约准入映射：** 依赖 CL-110 的契约补齐；本卡自身不触发端点准入，但它是 E-B01“引用可回跳”断言的观察面。

#### CL-119 `[R1A][P0][quality]` 固化资料闭环端到端验收证据

- **目标/产出：** 合法 PDF 从上传→解析→引用/纠错→取消/删除的桌面/移动 E2E，记录任务/版本/错误与操作时间；把 [CL-012c E 层矩阵](../quality/CL-012/uat-matrix-and-observation-log.md) 的 E-B01～E-B09 串成可重跑脚本与归档证据。
- **依赖：** CL-111、CL-112、CL-113、CL-114、CL-116、CL-117、CL-118。
- **验收/证据：** 普通、扫描、缺页、损坏、重复上传、重启、删除并发均有预期结果；每条用例保留请求/资源/Job/版本的可对账引用与前后事实；不通过场景列为阻断/已知限制；**不能宣称“资料已就绪”**。
- **No-Go 下的可推进边界：** **可在隔离研发下完成**：脚本骨架、合成夹具、两个隔离账户、受控故障注入、证据归档格式，先跑通 E-B03 权限负例与最小合法闭环。**必须等外部条件**：真实合法样本 `#39–#41`、供应商准入、CL-014b 复审（`#54`）通过；**真实用户不在本卡的 E 层范围内**（那属于 P 层与 `#49`）。**E2E 通过不自动解除任何 G 门。**
- **契约准入映射：** 本卡是条件 5 的集中验证面：它要求相关端点在**真实 HTTP** 上给出正确响应与错误，而不是手写 OpenAPI 或 mock 服务器。它不构成任何端点升级的依据；相反，端点未按六条准入改标时，本卡的对应用例只能标 `阻塞—API`。
