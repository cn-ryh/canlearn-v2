## 目标和交付边界

形成一套可评审、可供后续实现使用的设计包，回答四个问题：平台处理哪些数据、
谁有权执行哪些操作、撤回或删除如何覆盖所有副本、哪些攻击与失败必须被控制。

按现有 R0 拆分，CL-004 交付数据目录和生命周期设计、权限及素材使用矩阵、
威胁模型与后续验证方案。业务代码按原路线图落实到 CL-101/103/104/109/110、
CL-114/116/117/118 等后续卡；身份、存储、检索和模型供应商选择交给 CL-005，
正式实体/迁移、API、Job/事件契约分别交给 CL-006/007/008。
CL-004 将向这些任务提供明确约束和待决项，避免提前把候选方案写成实现事实。

规划覆盖已确认的完整 P0 范围：私有资料闭环、公共种子内容、生成讲解与练习、
作答和证据、近期计划及恢复、导出和删除。实际代码目前只有首页、健康接口、
基础 jobs 表和 Temporal 健康工作流，设计包须逐项标注现有、规划和待决状态。

## CL-004a 的具体工作

### 数据目录

先逐类盘点，再沿生成、复制、更新和删除路径补齐派生资产。目录至少覆盖：

- 账户/身份关联、私有/公共空间、学科与目标、容量配置。
- 原 PDF、文档/来源版本、使用权声明和审核记录。
- 页图、原始解析 JSON/Markdown、标准化区块、人工修订和质量记录。
- 分块、向量或其他检索索引、知识/技能关联和来源引用。
- 题干、答案、讲解、量规、校验结果与公共发布版本。
- 作答、证据、已完成任务、计划版本和恢复提案。
- Job 输入/输出引用、Temporal 历史/activity 载荷、失败回执、临时和孤立产物。
- Redis/客户端/下载缓存、导出包、签名访问凭据。
- 日志、追踪、分析事件、费用/审计最小记录、备份及恢复副本。
- MinerU/模型供应商收到的输入、中间文件、输出、日志及其删除回执。

每类记录：稳定编号、目的、敏感程度、所属权限域、权威写入方、保存位置和副本、
来源版本/依赖关系、可访问者、传出目的地、保留触发条件/期限、纠错/撤回/删除动作、
导出范围、失败重试/可核验证据、现有或规划状态。未决项注明负责角色和最迟决定节点。

保存位置以数据库、对象存储、索引、缓存、临时目录和供应商等逻辑位置描述；
具体厂商、地域、容量和固定期限通过后续选型/评审决定。

### 数据流与生命周期

画出 Web → API → worker/Adapter → MinerU/模型供应商，以及数据库、对象存储、
缓存、索引、日志与备份的信任边界；在每条数据外发路径标明目的、必要载荷和授权检查。
主 API 管理业务状态、权限与权威发布；worker/MinerU 的临时结果需要在相应门禁后接纳。
单独检查 Temporal history/activity 的持久化载荷，避免把原文和访问凭据遗留在工作流历史。

生命周期分别说明准入、处理中、可用、修订/撤回、访问撤销、在线清理、备份到期及恢复
后的行为。资源删除和 Job 取消分开表达；精确状态枚举与转换由 CL-006/008 接续。

删除路径须覆盖：立即撤销访问和新增任务 → 隔离在途/晚到结果 → 清理在线副本和
含原文的派生内容 → 跟踪供应商及缓存清理 → 备份按明确策略到期清除 → 恢复前应用
删除记录并核验。分别记录逻辑不可访问、在线清理完成和备份清除，不混用完成口径。

### 需要明确的边界

- 区分取消任务、删除单份资料、删除整个账户、公共内容撤回和供应商清理请求。
- 区分来源相关生成内容、历史作答事实及其中复制的原文；资料纠错/计划撤销不能改写
  历史事实，主动删除时哪些字段清理、遮蔽或保留则需独立规则及审批。
- 旧引用失效后不能继续用于检索或新生成；学习证据与计划受影响的范围交给 CL-006 细化。
- 分别定义自有数据导出与有用途限制的公共/第三方内容导出。
- 日志和分析事件仅保留必要元数据；署名/费用/审计的例外留存须有依据、范围和期限待审。

004a 验收采用合成案例逐条走查正常上传、版本纠错、资料删除、账户删除和备份恢复，
记录设计缺口；生产清理与恢复演练安排在对应功能落地后。

## CL-004b 的具体工作

### 主体、资源与操作

主体覆盖本人、其他用户、公共内容使用者、内容编辑/审校者、管理员/支持、
worker 服务身份、MinerU/模型供应商及匿名请求。资源覆盖 a 的资产及其版本、
任务、引用、下载/导出凭据和公共候选/已发布内容。

操作覆盖创建/上传、读原件、解析、检索、生成、修改/纠错、发布、下载/导出、
取消、撤回和删除。矩阵逐格写允许、拒绝或满足哪些条件后允许，避免用一个“管理员”
角色获得所有私有资料读取权；内部服务访问也需要明确资源、用途和有效期。

后续实现约束至少包括：服务端确定资源归属，私有默认拒绝跨空间访问，派生资产继承
权限，读取/检索/展示/导出/结果接纳各处复查版本和删除状态；缓存/哈希去重不能泄露
其他空间是否持有某文件；公共候选经相应审核后才进入可读发布版本。

### 素材权利与外发处理

素材类别区分私有上传、团队原创/合作、开放许可、商业教材/题库、官方公开信息与
外部链接。分别记录阅读、复制/存储、解析、模型处理、生成衍生内容、公开分发和导出
所需证据及限制；网页可访问、用户声明或字体许可均不替代各项用途的独立核验。

供应商检查表覆盖处理目的、必要输入、地域、留存、训练使用、分包、访问控制、
删除/退出与可核验证据；未选供应商的字段保留待定，不预设真实私有资料已获外发批准。

权利/许可证、个人数据处理安排由相应外部责任人核验，本文件记录待核验问题和
限制，不给出未核实的法律结论；公共内容同时登记学科审校责任和版本/用途。

004b 验收以两名合成用户、私有/公共候选/公共已发布内容和受限服务身份做矩阵走查，
覆盖猜测资源 ID、相同文件哈希、旧版本引用、删除后的下载和用途限制等负例。
真实来源和供应商条件的核验在具体来源/供应商可用后补齐，未取得证据的行保留待审。

## CL-004c 的具体工作

对每个情景记录入口、攻击主体、信任边界、前提、受影响数据、严重程度、预防/检测
控制点、失败预期、验证阶段/用例、负责及审核角色、残余风险和阻断条件。

| 情景 | 必须设计的控制/失败预期 | 后续实现或验证位置 |
| --- | --- | --- |
| IDOR / 跨空间资源、引用与导出 | 服务端逐资源授权；匿名/其他用户不能得到私有内容 | CL-101/109/110/116/118 |
| 跨空间哈希、缓存与索引泄露 | 权限域与版本隔离；命中/返回不暴露他人文件或已撤回内容 | CL-103/109/118 |
| 非法或恶意 PDF、超大/损坏文件 | 准入、安全扫描/隔离与资源限额；失败不启动后续处理 | CL-104/106/118 |
| 文档指令注入、模型越权调用 | 不可信资料不能改变系统权限、调用未授权工具或直写业务数据 | CL-005c、CL-118 及生成链路 |
| HTML/公式/代码内容执行 | 解析与展示隔离/清洗；内容不能执行宿主命令或客户端脚本 | CL-106/112/118 |
| 下载/签名 URL、导出包及日志泄露 | 最小授权、明确过期/撤销语义、日志不记录访问凭据或原文 | CL-103/110/116/117 |
| worker/Adapter 权限过大、任意下载目的地 | 受限服务权限、允许的目标/资源；结果由权威模块复核接纳 | CL-005/007/008、CL-106/114 |
| 取消、删除后晚到结果或重试复活 | 每步及接纳前检查权限/版本/删除标记；拒绝发布并清理孤立资产 | CL-008/114/117/118 |
| 旧来源/计划版本结果覆盖新版 | 明确基版本与冲突处理；不静默覆写已完成任务或作答 | CL-006/008、CL-113/114、R1B 计划链路 |
| 备份恢复或供应商残留恢复访问 | 恢复前应用删除记录、验证禁止读取；外部清理结果可追踪 | CL-005c/005d、CL-117、恢复演练 |
| 公共发布或外发用途越界 | 版本与用途检查；未签审或超许可范围保持不可发布/不可传出 | CL-009/010、CL-202 及供应商接入 |

注入和文件负例先作为不含真实用户数据的场景规格；具体合法夹具、自动化回归和
故障注入跟随相关接口/工作流落地。004c 不将设计走查记为安全测试已通过。

## 验证与交付条件

计划阶段只核对需求和依赖、检查 Markdown 链接及差异，未重跑业务测试。
本次设计交付不执行迁移或接入外部服务。此前 `pnpm verify` 通过仍仅代表此前已验证的工程基线。

确认后完成设计包时：

1. 对照三个 Issue 的验收点与完整 P0 范围做覆盖检查，每类资产/风险可追踪到规则或待决项。
2. 用合成资料和纸面走查复演正常、越权、纠错、取消/删除、晚到结果、导出和恢复场景；
   记录预期、矛盾与待验证项，不生成伪造的真实用户/竞品/供应商测试结果。
3. 检查三个子项间的权限域、来源版本、保留/删除与日志规则一致；检查本地链接与
   `git diff --check`。纯文档交付不把 `pnpm verify` 当作权利或安全验收。
4. 父项入口汇总实际评审、未决项与下游实现卡；外部签审或正式验证未到齐的部分保留
   对应状态，不自动关闭 Issue 或宣布 R0 放行。

业务 E2E、安全回归、真实 MinerU/供应商删除和生产恢复演练，分别在相关功能及环境
具备后补齐。真实访谈与竞品实测按其自身研究卡收集，与上述设计交付并行安排。
