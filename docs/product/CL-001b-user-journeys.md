# CL-001b · 可验证的首发用户旅程

状态：**体验验收草案，尚未用户测试** · 版本：0.1 · 2026-10-03

来源：V2.1 产品方案“三条首发用户路径”“核心场景输出契约”；CL-001b #16。以下是可供 CL-012 原型直接使用的演示脚本，不代表功能已实现。测试文件必须有可证明的使用权；不得将真实私有 PDF、姓名或访问凭证提交仓库。

## 共同验收定义

一次有效学习证据包含：用户实际完成约定任务、进行一次新的退出测或结构化回忆、结果关联至目标技能和来源，并有可信的作答/结果记录。答错仍可形成有效学习证据；登录、上传成功、生成内容或浏览本身不算。

三条路径都必须能看见资料/内容来源及其可用状态，知道任务估时与总容量影响，并能理解失败、等待、部分可用和下一步。AI 产物显示“试用生成”等准确校验标签；没有来源的内容须明确说明。

## 旅程 A：从公共 408 / CET 内容开始

**角色和前提：** 有明确备考目标的自主学习者；公共目录仅展示已准入、已授权和有学科审校记录的单元。首批之外或尚未审校的内容不得伪装成已发布。

**演示成功路径：**

1. 用户选择 408、四级或六级目标，填写基础情况和每周可用总时间。
2. 查看学科包维护状态、目录覆盖范围、来源/许可摘要和每个单元的内容状态；覆盖不足时可选择自己的资料，不被锁在单一资源体系。
3. 查看七日滚动任务及预计用时，确认后开始一个单元。
4. 阅读带来源标记的讲解，查看少量有校验等级的练习；对题目作答，得到反馈和可回到来源的位置。
5. 完成一次新退出测或结构化回忆，系统保留作答、技能和内容版本，显示这是一次学习证据而不是“已掌握”结论。

**失败/边界演示：**

- 目录没有相应学科或单元：明示覆盖缺口，允许转入私有资料路径；不声称全学科公共内容齐备。
- 某项内容被撤回或待审：阻止开始新的诊断/发布，说明状态和替代入口；已完成记录保留来源版本和失效状态。
- CET 听力资料未具备权利或产品没有音频能力：显示暂不支持音频处理，不用文本任务冒充听力测量。
- 总容量不足：明确说明可行范围和冲突，让用户调整优先级；不偷偷缩短估时或删除目标。
- 内容只有生成草稿/未过质量门：标明试用状态，不进入正式诊断或公共精选库。

**演示验收：** 测试者能指出此单元是否公共发布、依据是什么、练习校验状态、自己的本周容量及一次有效学习证据；系统不能将未审内容表示为正式事实。

## 旅程 B：用其他学科的私有 PDF 开始

**角色和前提：** 一名学习者有权为自己学习使用一份非 408/CET PDF。拥有文件不自动代表可以公开再分发；原件和派生资产默认为该用户私有。

**演示成功路径：**

1. 用户建立通用学科目标并上传 PDF，查看文件版本、大小/页数、预计处理范围及权限说明。
2. 系统异步处理，逐页展示成功、缺页、低质量或失败状态；仅允许选择通过质量门的章节。
3. 用户检查章节并选择一节；讲解包含文档版本、页序/引用定位或明确的无来源补充标签。
4. 用户跳回原 PDF 核对出处，指出识别问题时可以反馈/纠正；生成少量单选、填空或短答练习，显示校验等级。
5. 用户完成练习和新的回忆/退出测，得到关联来源及技能的真实作答记录。随后可选择建立计划；不强迫先填写冗长档案。

**失败/边界演示：**

- 格式错误、加密/损坏、超出明确限额或权限声明不清：在解析前说明问题，不启动隐式上传/处理。
- 解析部分成功：展示可用和不可用页；缺页不能由模型补造，用户只可对通过质量门的章节学习。
- 用户取消或任务超时：说明当前阶段、是否存在可用结果和重试影响；晚到结果不能在取消/删除后复活资料。
- 用户请求删除：先撤销访问和新任务，再显示在线派生资产清理及备份处理状态；删除完成后检索和引用均不可访问。
- 另一个空间尝试访问相同资源或缓存：必须拒绝，不能用共享哈希/缓存越过空间边界。

**演示验收：** 从合法 PDF 起步，能够找到引用对应的文件版本和页；能区分部分可用与全部完成；正确作答与错误作答都形成忠实记录；删除和取消之后无晚到内容复活。

## 旅程 C：学习中断后恢复

**角色和前提：** 用户此前已确认一周计划，完成了一部分任务并留下实际作答；本周突然少出两小时或发现某节有理解缺口。

**演示成功路径：**

1. 用户说明本周可用时间减少，或选中有困难的知识点。
2. 系统先汇总已完成/未完成任务、来源与证据缺口、剩余容量；已完成任务和真实作答保持不变。
3. 显示保底、平衡、冲刺等不同可行范围、时间总计、延期影响和证据覆盖，明确哪些目标无法全部完成。
4. 用户查看差异后确认其中一个方案，或拒绝并保留原计划；确认前不得悄悄重排。
5. 如用户改变主意，在没有破坏性新变更时可撤销到上一个计划版本；恢复后继续学习并留下新的、可追溯结果。

**失败/边界演示：**

- 剩余任务超过可用容量：输出不可行和建议取舍，不压缩任务时长或谎报全部可完成。
- 计划在用户查看期间被另一处修改：提示版本冲突，刷新差异再决定；旧提案不得覆盖新版本。
- 用户拒绝提案、离开页面或恢复建议失败：旧计划和完成证据仍可见，没有任何未确认的变化。
- 已完成任务进入候选重排：规则排除它，作答不删除、不改分，也不撤销历史证据。

**演示验收：** 任一观察者可从计划版本看出发生了什么变化、谁确认、哪些任务已完成和恢复后还剩多少时间；拒绝与撤销不会抹掉真实学习记录。
