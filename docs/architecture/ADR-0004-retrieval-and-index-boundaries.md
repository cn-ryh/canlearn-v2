# ADR-0004：检索索引与 PostgreSQL 职责

- 状态：BGE-M3＋512 token/batch 4 为内部原型推荐；隔离控制与长块/无答案/GPU补测已有证据，正式质量/评审待 CL-009
- 日期：2026-10-12
- 对应：CL-005b / #27；A（任宇航）主责、B 复核，C 验证
- 决策上下文：[CL-005 入口](CL-005/README.md)、[CL-004 数据目录](../security/CL-004/data-inventory-and-lifecycle.md)

## 问题与候选

中英文资料需要可追溯分块、章节范围、检索权限和来源版本过滤；默认 PostgreSQL 全文配置
不能直接视为合格的中文词法检索。向量检索不会自动解决多租户隔离、原文删除或答案泄露。

| 候选 | 收益 | 成本/限制 |
| --- | --- | --- |
| PostgreSQL＋词法检索＋pgvector | 复用现有事实库，减少独立服务；可比较精确与近似搜索 | 扩展可用性待核；索引竞争 DB 内存/CPU，中文分词及召回需实测 |
| PostgreSQL＋词法检索，暂不启用向量 | 依赖与外发较少，可先验证章节/关键词路径 | 必须证明 P0 的同义/概念检索可用，明确偏离产品全文＋向量规划的阶段范围并经确认 |
| 独立检索/向量服务 | 独立扩缩容与索引负载隔离 | 新增服务、同步、删除传播与运维；当前未有规模证据支持优先引入 |

## 推荐提案

2026-10-12 用户选择本地多语言 embedding 优先，接受10人以内、每人5份20–100页的测算，
另加300页合成观察样本，不要求解析必定成功。已完成 [检索核验与容量设计](CL-005/retrieval/README.md)：
PostgreSQL17.11＋pgvector0.8.7＋jieba0.42.1 原型的10项控制检查通过；
采用人工3维向量，不是语义召回或性能测试。随后经用户授权在4070上运行
BGE-M3/E5-small固定revision的真实模型烟测：8段原创资料、16个中英文查询，
Top1分别15/16和14/16，Top3均16/16；独立进程显存/热查询结果见检索记录。
补充 [长块/无答案/GPU共用评测](CL-005/retrieval/extended-evaluation.md)：BGE-M3 的512/1024/2048
token、batch 4 吞吐分别39.156/17.778/7.269块每秒，长重复背景没有稳定质量收益。
推荐内部原型使用既定 BGE-M3 revision 的稠密1024维向量、512 token目标上限、batch 4，
1024只作不可拆语义对象的例外候选，2048不作为默认；按实际tokenizer计入特殊token，
保留语义/来源边界，不为凑长度拼接无关内容。重叠、例外和最终质量门由 CL-009 真值决定。
E5保持轻量比较候选，超过512token的尾部事实实测不会进入模型；其前缀也占长度预算。
不混用两个向量空间，CPU查询也应保持与文档相同的模型/配置。

16个有答案查询加入8个干扰段落后，两模型Top1均12/16、Top3均16/16；12个无答案查询
与有答案Top1分数区间重叠，BGE无答案最高0.693051、高于有答案最低0.464605。
资料可能讲删除流程但缺少所问的期限，不能把主题相似或领先分数当作支持答案的证据。
不冻结单一余弦拒答阈值；证据覆盖判定、误接纳/错误拒绝、词法融合/重排与引用定位
须在 CL-009 冻结的真实样本校准/留出集预登记并验证。

MinerU4.0.7 Basic/Torch已在独立环境对300页合成文件串行解析并保留300个页锚点；
测试中10秒到达的BGE查询实际排队约98秒，不能作为实时查询的默认等待方式。
建议解析与文档embedding串行调度，查询独立限流/超时；同模型BGE四线程CPU查询
在宁波主机中位约105ms，可作为继续验证的候选，不外推南京4核8G的容量。
并发只按指定档位实测证据评估，不从Basic或短查询推定Standard/VLM或持续10用户可并发。
解析结果本身仍须经过权限/版本/质量接纳，页锚点存活不等于正文/公式完整准确。

先评估 PostgreSQL＋pgvector 的小规模混合检索，中文分词策略单独比较。
先从明确页/章节范围构建语义对象块，保留父子关系、来源版本、页/区域、质量状态与用途；
上述分块/模型作为内部原型推荐，正式分块、重叠及模型质量通过 CL-009 合法样本验证。

小规模优先对授权范围比较精确向量检索与词法候选，再根据召回、延迟、成本确定融合策略。
pgvector 官方文档指出近似索引条件过滤后可能不足 k 个结果；后续使用 HNSW/IVFFlat 时，
需比较迭代扫描、分区或其他索引策略，不能靠增加返回数量解决权限问题。

API 从服务端身份确定资源范围；查询必须包含归属/权限域、用途、已确认质量、可用于新检索的来源版本、
删除/撤回条件，候选回传前再次核验资源状态。数据库行级保护可作为纵深措施，
具体 DB 角色与连接上下文待 CL-006/007 决定，不将超级用户连接视为有效隔离。
禁止从全局未授权候选集向客户端回传命中率、文件存在性或私有原文。
诊断新题检索排除已曝光答案/解析，历史回跳与新检索资格分别判定。

PostgreSQL 保存来源、版本、授权、内容事实、删除台账和索引发布状态；向量及词法索引是派生数据，
可同库存放但重建不改变业务事实。索引记录 embedding/分块版本及来源依赖，不让向量成为唯一内容副本。

embedding 优先比较现有 GPU/CPU 本地模型与已核验外部服务；本地算力仍有时延、电力和运维成本。
4070 还需解析任务，不能默认两者可以并发；外部 embedding 与生成同样检查地域/留存/训练和用途。

## 删除、恢复、失败与退出

资源撤回/删除先影响 API 可读与新检索，再异步清块/向量/词法及缓存；索引结果不能绕过事实状态。
索引重建从获准版本读取，使用独立索引 generation，校验覆盖、版本/权限与删除水位后切换。
旧代索引失去访问资格并清理；失败不静默回退到已过期/已删除内容。
数据库复制/索引重建/旧备份恢复必须先应用最新删除记录，不能以重新计算“复活”资料。

验证两用户同哈希、混合来源、旧版本、撤回/删除并发、缺索引、错模型维度、重建中断与召回/延迟。
单库资源压力或检索质量不满足时再评估独立服务；迁移用稳定块 ID、来源与模型版本导出，
双路校验授权结果后切换，旧索引禁读并清理。更换 embedding 模型需要新代重建，不混用维度或距离语义。
