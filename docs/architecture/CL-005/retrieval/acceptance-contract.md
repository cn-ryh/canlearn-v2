# CL-005b 评审修订：检索边界与合成贯通验收

A＝任宇航负责路线与安全批准，B 实现，C 验证；B/C 实际人员待指定。

## 当前证据边界

人工三维向量的 SQL 探针、固定 BGE 模型烟测、300 页 MinerU 解析是三条独立实验路径，
尚未形成“解析→分块→embedding→入库→授权检索→引用回跳”整体证据。
RLS 主要限制所有者/公共可见性；当前版本、确认质量、用途、墓碑、发布代主要由检索 SQL 判断。
重建中断实验主要证明发布指针事务回滚，不能证明构建中删源/纠错/撤权安全。
加入干扰后两模型 Top1 均 12/16、分数区间重叠；BGE 是原型推荐，余弦分数不能判定证据充分。
512 token、batch 4 是工程初值，不是质量承诺；真实合法样本及双标继续交 CL-009。

## 查询执行位置与服务目标

选定内部试点的首选实现位置为南京独立受限 CPU 查询进程，与 API/数据库/Temporal 同机，
使用与文档索引完全相同的 BGE revision、tokenizer、pooling、归一化和维度；
不接入解析 GPU FIFO，不混用 E5。模型常驻内存必须计入南京 8G 混合负载，尚未验证可容纳。
宁波 CPU 的约 105ms 单查询不是南京服务指标。若资源不足，先禁止启用该查询路径，
由 A 另行评审独立服务位置和数据路径；不能静默退到拥堵 GPU、外部模型或旧索引。

候选目标由 A 在 CL-109 负载测试前批准：检索端到端 P95≤2秒、硬截止3秒、
查询 embedding 排队≤200ms、进程并发1/候队4；超队立即429，服务不可用503，截止504。
这些是内部检索目标，不含后续生成；不能把超时当“没有答案”。
P95 从 API 收到已认证查询开始，包含授权、排队、embedding、SQL、融合与最终授权，
失败率/拒绝率和全部请求耗时一同报告，不能只对成功请求选择性报指标。
测试南京真实 4核8G 上 DB/Temporal/API/CPU worker 共存，在10个合成账户、
1/2/4/10并发、2千/1万/5万块档位分别暖机并至少采样200请求；冷启动、慢DB、
解析并行、过载和服务断链单列。报告 RSS/CPU/磁盘、队列长度、P50/P95/P99、错误率与原始样本。
B 实现、C 留证；未达目标不能以宁波单查询数替代验收，也不据小样本冻结用户 SLA。

## 唯一授权入口

CL-101/109/110 由 API 封装同一资源资格策略，词法/向量/融合、正文回跳、导出和内部 worker 读取共用：
服务端身份、空间成员状态、来源版本、质量确认、用途、墓碑/撤回、发布 generation 及其依赖修订必须同时有效。
多来源对象取所有依赖权限/用途的交集；一项撤销整个候选失效，不靠返回后遮掩片段。
RLS 是纵深控制；业务连接必须非超级用户、非表所有者且 NOBYPASSRLS，禁止业务池绕过策略直读。
上下文只由可信 API 在事务内 SET LOCAL；提交/回滚、取消、连接归还后不能泄漏到下一请求。

最终接纳与撤销事务按资源/授权 epoch 协调：候选生成时捕获 epoch，发布/读取最终校验时
以一致锁顺序锁定依赖或 CAS 当前版本与全部 epoch，撤销提交在前则候选必须失败。
读取接纳先提交的请求可能已有字节在途；撤销后新请求一律拒绝，不能承诺追回旧字节。
查询缓存绑定身份/用途/来源修订/权限 epoch/删除水位/代，命中仍复查资格；
生成模型调用前亦重查，检索时有权限不能永久授权后续付费执行。
C 验证连接池跨用户复用、缺上下文、事务异常、多来源交集、候选形成后撤权、回跳前删源。

## 合成纵向链路交付

CL-107/108/109/110 接续，B 交付可运行脚本/测试，C 独立运行；先用仓库原创合成 PDF，
固定 SHA、MinerU 版本/档位、真实解析输出摘要及 BGE revision，不以手写三维向量代替模型。
300 页资料纳入独立容量观察，完整性/引用检查与复杂教材质量分别报告。

1. 解析产物记录原始文件版本、页/区域与失败页，缺页不标完整；更正产生新解析修订。
2. 依据结构生成稳定块 ID，记录页/区域、父子、源修订、token 实际计数与截断标志；
   公式/表格/跨页定义不可为凑512盲切，超限对象按结构子块＋父引用或显式不支持处理。
3. 用固定真实模型生成1024维向量，向量与词法记录绑定模型/分块配置和索引代；
   非有限值、错维度、缺块和未知质量不得进入发布代。
4. 两个合成账户、同哈希不同归属、私有与公共资料分别入库；真实 API 经唯一策略检索，
   命中引用回跳到精确源版本/页/区域，检查可见原文与摘要一致，拒绝旧/删/未确认候选。
5. 固定有答案、干扰、无答案、缺证据查询，预登记期望引用与禁止引用；
   无充分证据返回明确状态，不用余弦阈值伪装充分性判断。记录召回/错引/误接纳与误拒，
   仅作原创合成烟测，不能替代 CL-009 的真实质量校准与留出集。

归档输入/输出/配置摘要、命令、依赖锁定、逐步 trace、数据库断言、HTTP 回跳结果、
失败与清理结果；上述材料缺失即仍为未贯通。真实资料入口继续受 CL-009 与供应商/权利准入约束。

## 索引构建、发布与恢复并发矩阵

构建快照记录每个来源修订、授权/质量 epoch 和删除日志水位；新代保持不可见。
发布事务重新核对全部依赖及最新可验证删除水位，并以 CAS 切换发布指针。
构建开始的快照校验不能替代发布时校验；任一失配将该构建标废弃或重建，不发布旧候选。
校验与切换必须在同一原子保护内，不能先校验后无锁更新；最终读取仍检查当前资格。
全局删除水位变化可以保守拒绝重建，不允许为提高可用性忽略未消费日志。

| C 必测时序 | 应有结果 |
| --- | --- |
| 快照后/写块前删源 | 不发布，已生成块不可读并清理 |
| 写块后/切换前删源 | 发布 CAS 失败，旧代也受墓碑拦截 |
| 校验与切换同时撤权 | 由同一锁/epoch 决定顺序；撤权先提交则切换失败 |
| 构建中来源更正/质量撤回 | 修订/质量 epoch 不匹配，旧构建不得发布 |
| 多来源仅一个权限撤销 | 整个依赖对象失效，不保留其他来源包装的泄露片段 |
| 两构建同时发布 | 基代 CAS 仅一个成功，失败者不覆盖新代 |
| 切换提交后 ACK 丢失/worker 强停 | 查询持久发布事实恢复，不无条件回滚或覆盖 |
| 发布前重启/清理失败 | 不可见中间代可重试清理，删除/撤权优先 |
| 旧备份＋新删除/撤权日志 | 隔离恢复并补齐日志再重建/开放；缺最新日志禁止服务 |

真实 SQL 并发屏障/故障注入和旧备份恢复必须交付实际结果，纯内存推演不作通过证据。
A 安全复核、B 实现、C 验证；CL-109 发布功能、CL-112 更正传播、CL-117 删除及首次持久试点前分别验收，
恢复流程对齐[内部运行合同](../internal-operations-contract.md)，不得拖到生产上线后再补。
