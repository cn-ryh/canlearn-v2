## 服务端准入规则

每次外部调用由主 API 在 Job/Usage 事务内按精确四元组
`(provider_id, provider_config_version, purpose, data_class)`匹配有效批准记录。
数据类别由来源权利/权限快照推导，不能由 Web、模型或 worker 自报“合成”；多来源取最严格类别。
用途至少区分 generate / validate / repair，数据类别区分 synthetic / private / restricted。
记录包含 approval_id、证据引用、实际审批人、有效区间、可用路由及版本、地域/数据条件摘要、
价格快照、次数/并发/预算上限、当前撤销 revision。任一字段/版本未知、过期、撤销或不匹配即拒绝。
默认无记录即拒绝；不能把已批准 generate 自动扩展为 validate，也不能按相同别名继承新配置批准。

worker 仅拿一次性 admission 引用及服务端绑定配置，不持绕过 API 的任意模型路由能力。
API 原子检查账户/来源/用途/取消删除、批准 revision、预算及在途上限后，写唯一步骤尝试和预留，
再派发；执行前复查撤销，接纳结果时再次检查。撤销不删除已发请求和未知费用事实。
供应商切换/配置变化是新版本重新批准，不自动降级；Redis、环境变量和研究 JSON 不能替代权威记录。
缺保守费用上限或有效价格/预算配置时，不准入正式付费步骤。合成研究获准调用不代表真实资料准入。

准入负例必须覆盖：未知配置、错用途、伪报数据类别、过期/撤销批准、旧 epoch、超预算、同键异载荷，
以及 worker 重启后不能凭旧 admission 新发一次请求。真实 SQL/HTTP 证据由后续实现卡提供。

## 次数、执行未知与费用未知分别处理

每条链至多四次潜在付费调用：生成、跨别名校验、一次修复、修复校验；全部实际发送尝试都计数，
包括超时、失败、显式人工新尝试。SDK 保持 max_retries=0。四次上限不能替代预算/并发上限。
每 Job 至多一个执行结果未决的外部调用；unknown 继续占用原账户及全局在途名额，不能靠租约到期释放。

| 已有尝试 | 下一步允许行为 | 原预留/结果 |
| --- | --- | --- |
| 收到完整终止输出、身份/协议匹配、质量不合格，已确认本次计算结束 | 在修复次数、批准用途、来源/epoch和总预算仍满足时，单独准入一次 repair | 旧费用结算；新调用另预留，不覆盖旧尝试 |
| 已确认终止输出，但 usage/最终扣款未知 | 不等于执行仍在途；仅当旧未知费用继续全额占用且足以同时承担新预留、终止证据可靠时才可修复，否则暂停对账 | billing_unknown 不填0、不释放旧预留；后续账单追加更正 |
| 超时/断流/主动关闭、创建 ACK 丢失、worker 失联，不能证明远端结束 | 标 execution_unknown，暂停整条生成链；不得自动 repair、validate、重试、换别名或新建等价 Job 绕过 | 保留最坏已批准预留及在途名额；部分输出不发布 |
| 远端确认已结束且可取回同一次完整结果 | 对账原 attempt，校验后继续既有链，不重发生成 | 费用未知仍留预留；迟到结果仍受取消/删除/版本围栏 |
| 取得可核验停止/失败证据，但仍无合格输出 | 原尝试结束；新尝试必须显式授权、独立预留、重查所有准入条件并计入四次上限 | 只释放已确认无需支付的部分；不承诺取消退款 |

费用预留按最坏获批范围继续占用；结算超过预留触发 disputed/暂停，而不是给余额记负后继续调用。
未知费用、已确认费用、可释放余额分别记账。新计划、超时、逻辑取消、Temporal retry 或重新登录都不清零未知项。
不同 Job 也只能在旧预留/名额仍占用后的剩余预算及并发内准入，不能无限生成新 Job 规避挂起。
若供应商支持幂等/状态查询，只可按已批准协议对账原请求；未证实幂等不能重发 POST 来“找回”结果。
元数据查询若可能产生费用，也需已知价格和相应准入；不靠新付费生成猜原 usage。

历史 Step 48题链在120秒期限后继续修复，属于研究探针：其“整链通过”只指后续候选过了当时质量门，
不是执行互斥/预算安全通过。按本修订的默认正式策略，该链应在 execution_unknown 暂停，不能自动修复。
旧结果/费用/失败原样保留，未回写为通过新合同，也未再发调用消除未知状态。

## 独立校验器测试集与度量

DeepSeek＋Step 是跨别名实验，不称“独立模型保障”；同一聚合入口可能共享上游，实际独立性未知。
新增[原创校验器挑战集](validator-challenge-set.json)，与历史六类重复算术任务分开：
固定来源包、逐案候选、人工可算的期望判定和错误类别，正例与错误答案/错误引用/证据不足各3例。
来源卡包含当前版、撤回版、同名其他空间诱饵及资料缺失情形，不把模型自评当真值。
这是待 C 复核的合成设计真值；不是 CL-009 真人双标或教学留出集。

正式验收以冻结候选输入逐例送入校验器，不再让生成器先筛掉难例；独立求解先不看候选答案，
再按精确来源版本、空间和用途核引用。代码校验与人工复核分别留证，模型别名不能代表独立性证明。
错误答案、错误引用、证据不足分别报告 `误接纳数/该类负例总数`；正确结果报告
`误拒数/正例总数`，另列 abstain/unknown、传输失败与有效样本数，不从分母静默剔除失败。
每类3例只做门禁烟测，不冻结正式教学阈值或声称可靠概率；上规模仍依 CL-009 合法留出集。
本轮仅冻结12例及协议，没有运行任何模型校验器；各项误接纳/误拒率均为未测，不能填0。
