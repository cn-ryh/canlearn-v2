## 统一设计约束

以下来自已确认范围和 ADR；具体方案仍须在对应选型/模型/契约任务中落地。

1. 前端访问 CanLearn API。主 API 管理权限、业务状态和权威发布；worker 受限执行，
   其临时结果须经权限、版本、取消/删除和质量检查后接纳。
2. PostgreSQL 保存业务事实，Redis 保存可重建状态。文件、索引和供应商副本各自登记；
   Redis AOF、Temporal 历史和恢复副本不能因“缓存/任务”名称被遗漏。
3. 私有资料与派生资产默认隔离；客户端给出的空间 ID、文件哈希或来源引用不能授予权限。
   读取、检索、展示、导出及异步结果接纳均需要关联实际资源并复查访问状态。
4. 取消任务、删除资料、删除账户和撤回公共内容分别定义范围。资料删除首先阻止访问
   与新增工作，再跟踪在线清理、外部清理及备份到期；晚到结果不能恢复访问。
5. 纠错和计划撤销不覆写真实历史事实。主动删除时，历史事实、原文副本和个人关联的
   处理单独核验，不从“不可变作答”推出永久保留用户数据。
6. 已生成下载包、签名 URL 和供应商副本均可能独立于数据库状态存在。
   撤销能力未知时不能承诺所有下载立即失效；访问路径和完成口径必须满足 Q07 后才能放行。
7. 公共候选、已发布版本、私人处理和对外模型处理分别检查用途。
   用户声明、公开页面可访问或字体许可均不自动提供其他处理/分发用途的许可。
8. 日志、分析事件和任务历史优先保存必要元数据和受控资源引用。
   原文、模型完整提示、令牌及带签名链接不得成为无清理路径的持久化载荷。
