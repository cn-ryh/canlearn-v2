# CL-014b · R0 → R1A 阶段放行决定

版本：1.0 · 2026-11-10 · 对应：CL-014b / GitHub #54，父卡 CL-014 / #14

证据基线：本地提交 `769a155886171e53fbc512584f0212b6880ae4b4`；Issue 状态核对于 2026-11-10。

## 1. 决定

**No-Go：当前不进入真实用户 R1A 试点。**

本决定只禁止把现有成果解释为真实用户、真实私有资料或生产用途的放行。可以继续的工作严格限于：

- 使用团队原创、合成或已明确获准资料的隔离桩、mock 原型、契约与数据模型研发；
- 默认关闭、访问受限的合成 Job / MinerU 工程探针及其非作者复核；
- 不处理真实个人资料、不调用未准入供应商、不发生真实用户付费任务的测试。

**这不是“限范围生产 Go”或“限范围真实用户 Go”。** 当前不得据此开放真实私有资料上传、公共发布、正式诊断、未成年人招募/注册/试点或未核验的供应商外发。原型、OpenAPI、事件 Schema、合成烟测和隔离 MinerU 探针均不得改写为相应生产能力已上线。

No-Go 的直接依据是下述 P0 证据缺口，而不是进度压力或 P1 竞品实测缺口。本决定不宣称所有 R0 工作已完成，不豁免任何父卡验收，也**不自动关闭父卡 #14**。

## 2. 证据口径与分类

- “已有交付”只覆盖本地工件及其实际标明的测试范围；GitHub Issue 的 Closed 状态不替代运行证据、非作者复核或外部签审。
- **P0-H（硬阻断）**：对应安全、权利、真实用户或关键闭环证据不足；未解除前不得进入真实用户 R1A。
- **P0-R（R0 综合证据阻断）**：定义稿可继续使用，但不足以宣称 R0 综合验收完成；不单独扩大某项技术能力的使用范围。
- **P1-D（可解释延期）**：不是本次 No-Go 的独立理由；必须保留未测事实、责任与复审入口，不得写成已完成。
- 下表逐项覆盖 14 个父卡，并纳入 #54 指定的关键子卡。后续去向是接续位置，不是自动重开、关闭或重新指派 Issue。

## 4. P0 硬阻断与 P1 延期结论

### 4.1 当前 P0 硬阻断

1. **权利、隐私、学科、未成年人和供应商边界未获所需外部签审。** 对应用途一律不开放，开发自审或用户上传声明不能替代。
2. **合法样本和独立双标为零。** 因而没有真实解析质量基准，也不能支撑 #44 的合法样本档位/成本/兼容结论。
3. **真实用户证据为空。** #20 没有真实试访，#49 没有真实 UAT；不可推断需求、可用性、恢复接受度或学习价值已验证。
4. **真实资料业务闭环未验收。** 生产身份/权限、上传、业务 API/事件、私有对象存储、删除/备份恢复、目标网络/容量、预算与供应商对账仍有明确缺口。
5. **实际非作者审核、验收与外部责任记录不全。** 现有 Issue 关闭或 agent 文档核对不能代签。

以上任一项均不能以时间压力、平均指标、单次成功探针或缩减公告文案豁免。继续隔离研发不等于这些硬阻断已解除。

### 4.2 P1 竞品实测

CL-003b / #22 的访问实测未完成，但作为 **P1-D** 可解释延期，**不是本次 No-Go 的独立原因**。延期只表示暂不把它作为 P0 放行证据，不表示竞品任务已完成，也不允许用官网宣传、CanLearn mock 或推测填写结果。若后续转为实测，应回到 #22 保存可重跑记录；若继续延期，复审纪要须写明范围、待指派责任和补测入口。
