# CL-014a · 关键风险与外部签审台账

版本：0.1 · 2026-11-09 · 状态：**风险已登记，外部签审与 R0 放行未完成**

对应 CL-014a / #53。内部台账主责为 A（任宇航），D 负责非作者审核；实际审核和验收记录尚未签署。
本稿登记 R0 风险、责任与限制，不替代外部学科、权利、隐私或法律意见，也不构成 R0 → R1A 放行决定。

## 1. 责任与状态口径

- A = 任宇航；B = 前后端工程师；C = 解析与质量；D = 体验与验收。B/C/D 按仓库既有约定保留代号，
  姓名待登记。下表为每项风险指定的**内部实际主责**，不能用“外部待指派”代替内部跟进责任。
- 外部责任人单独登记在第 3 节。外部签署人、审核人均为“待指派”，日期留空；没有伪造签署、授权或验收记录。
- 状态“阻断”表示对应操作**不开放**；“开放”只表示风险未关闭，不表示功能已获准上线；
  “部分缓解”只限于已有证据覆盖的版本、样本和环境。
- 高风险必须同时保留内部主责、阻断条件和可执行的替代路径。技术测试、开发自审、平均指标或时间压力均不能豁免硬门。
- 期限采用依赖任务和阶段节点，不虚构已承诺日历日期。风险、来源、版本、用途或供应商变化时立即重审，不等原定节点。

### 当前高优先级阻断汇总

1. R01–R05 的外部责任人均待指派，未获所需外部审校或许可签署的事项一律标为**不开放**；
   四人团队可以推进受限研发，但不能自己批准这些外部事项。
2. R06 已有固定版本的恢复探针，但上游重启后原任务索引可丢失；未知创建不得自动重做，
   现有证据不能外推为生产派发、私有存储、物理 GPU 停止或长期容量已验证。
3. R07–R09 必须用实际样本、成本与容量证据更新；缺少证据时缩小结论和开放范围，不填估算数字冒充实测。

## 4. 更新、验收与回退

- C/D 及对应实现人向 A 提交脱敏证据，A 每周汇总；CL-014b 根据全部硬门和残余风险决定 Go、限范围 Go 或 No-Go。
- 风险关闭需要对应实现、负例/失败回归、非作者复核及必要外部签审；只有设计或单次成功测试时保持开放。
- 任何风险降级须写明新证据、覆盖范围和剩余限制。不得以“平均成功率”“用户已上传”或“供应商接口成功”关闭外部风险。
- 触发阻断时先停止新准入、外发、发布或付费步骤，保留必要审计和对账状态；晚到结果隔离，不复活已取消/删除资产。
- 回退只缩小开放范围，不删除原始风险证据或伪造完成。供应商退出、恢复环境和人工重建分别按对应任务核验后再开放。

| --- | --- |

| 外部签审 | 全部待指派、未签署；对应限制见第 3 节，不由开发自批 |
