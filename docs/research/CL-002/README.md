## 执行顺序

1. D 指定执行人，A/B 指定非作者审核人，填写同意说明中的联系人、保存位置、访问者和保留/删除安排。角色占位沿用用户在 CL-001 的决定，但正式招募前必须有真实可联系的人。
2. 将 `templates/` 中空白文件复制到仓库根目录的 `research-private/CL-002/`。该目录已被 Git 忽略；完成的记录、联系方式映射、同意凭据和原件不得进入 Git 或公开 Issue。
3. 按招募表筛选，取得分项同意后，以同一主脚本各试访至少一名 408、CET、其他学科用户。先验证脚本可用性，再滚动招募至三组各约 12 人；其他组整体至少覆盖三个学科。
4. 为每场创建会话编号，记录实际操作、失败/拒绝和人工投入。人工操作必须显式标记，不能报告为产品自动能力。
5. 以去标识的内部证据填写探索报告，披露缺口/偏差；公开工件仅保留空白模板和经审核的汇总结论，不能附原始访谈或可识别案例。

## 验收与回退

- a：筛选、同意、联系/退出机制和目标/实际/缺口台账经审核；有可执行的数据处理安排。
- b：记录可复现一次资料输入→来源核对→练习→减少本周两小时→恢复提案的礼宾会话，区分口头回答、真实行为、提示和人工介入；人工工时与费用可追溯。
- c：三组各至少一场已同意的真实试访，有成功/失败、权利/质量问题、恢复接受/拒绝和未验证假设。其他组扩展覆盖至少三个学科；未达到约 36 人建议目标时明确只为探索。
- 父项：A 汇总审核证据、实际样本和缺口后作结论。材料准备不等于访谈完成；不自动关闭远端 Issue。
- 无合法可用资料时改用事先核验的原创夹具，并记录“未验证用户自有资料路径”；无原型时采用纸面/文档礼宾，记录模式；缺真实受访者时保留未完成状态，不用虚构案例填数。

本次仅增加研究文档与空白模板，无 API/事件/迁移变更；代码测试不适用。依据为 [R0 拆分](../../roadmap/CanLearn_V2.1_R0_Issue_Split.md)、[CL-001 旅程](../../product/CL-001b-user-journeys.md) 和产品方案“验证体系与指标设计”。
